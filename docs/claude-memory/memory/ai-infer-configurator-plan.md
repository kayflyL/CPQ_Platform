- **复现为纲(09-27晚用户重申,高于一切自定义)**:先原样复现 Excel 功能清单,再叠加平台自定义。Excel 本体=「GPU配置器」选卡试算 → 已复刻为配置器主区「按卡试算」(/api/gpu-sizing/cards + /try-card,36 卡任选×张数→四档判定);框架下拉已放开(系数读表)。**「哪些机型支持这张卡」直读配件现成字段 kp_parts.applicable(系列级),GPU 卡 0/36 未填——别发明 gpu_slots 推算**;机型判定列表(gpu_default 出货口径)已从主界面撤下(主语=卡,机型是卡的下游);候选卡排行(速查表动态版)后置。教训:组件 v1 我连造了判定域/能力口径匹配等新机制,被用户叫停两次——**动手前先对照源功能清单逐条对账**。

- **「所有按钮点不动」终局(09-28,浏览器实测抓到两个叠加真凶,均已修)**:①后端 /evaluate 响应**缺 `need` 块**(前端 TS 接口声明了它,卡砖模板裸读 `evalRes!.need.weight_gb` → 渲染期 TypeError → patch 中止 → **全页事件绑定死——模板一处裸读 undefined 足以杀死整页交互,症状像"按钮坏了"其实是渲染崩溃**);②前端 evaluate() 的 loading 只置 true **从不复位**(缺 finally)→ 首算后后续所有试算被 `if(loading) return` 静默吞(「点了没反应/一直计算中」)。修法=evaluate 响应补 need + `finally{loading=false}` + overN 随新结果重置 + tiles 包 `v-if="evalRes?.need && evalRes?.params"` 兜底。教训:**契约冒烟必须断言响应完整字段形状——"200 且有数字"不算过**(此前 smoke 只验了 solve 没 shape-check evaluate);异步置位标志必须 finally 复位;`watch([多源], fn)` 会把 newValue 数组漏进 fn,必须包成 `() => fn()`。复现手法留档:preview 起 frontend-verify(launch.json,VITE_API_TARGET→8010 的 backend-verify,AUTH_ENABLED=false)+ localStorage 注入 `create_access_token` 签的 admin token(不动密码),即可全自动点完整链路。
