2026-08-05 配件库视图改造翻车：用户嫌配件库"重复性高、乱"，我提案"产品族折叠视图"并实现了独立组件 + 第三视图模式(卡片/表格/产品族三选一) + 后端族聚合 + config。用户怒斥"加个产品族 + 原表格卡片没精简 = 更复杂更不好用，完全不能用"，要求**彻底移除**(组件/端点/方法/config 种子/DB 记录全删)。

**Why:** 用户要的是「精简」(用族组织替代扁平卡片/表格)，我理解成「新增族视图模式」，结果变成"扁平模式原样没动 + 又多一个并列选项"，违背精简初衷 = 增复杂度。而且大功能(组件+后端+config)做完才给用户看，翻车成本高（时间和 token 全废）。

**How to apply:**
- 用户说"乱/重复/不好用"时，默认诉求是「精简」(删/合并/重构现有)，不是「加功能」。先问清精简程度：砍旧模式 vs 融入现有 vs 纯新增——这个分叉点必须先确认。
- 改视图结构(列表/卡片/表格/抽屉/视图模式)属高风险视觉/交互改动，务必**先确认方向再动手**，别直接实现一版让用户验收。强化 [[visual-changes-let-user-confirm-first]]。
- "产品族/物料组"这类分组概念，业内是「组织维度」(融入现有视图做分组)，不是「独立视图模式」。真要做就改现有列表按族分组，别加并列按钮。
- 大功能先出方案确认分叉点，比做完再被否成本低得多。
