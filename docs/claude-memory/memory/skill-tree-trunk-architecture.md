2026-09-02 用户定调（需求分析 skill 架构铁律，所有后续改造必须遵守）：

**五条铁律**：①单一权威源，同一份东西只存一处（用户上周已清空种子文件，能进 DB 的全进 DB）；②提示词 DB 唯一权威、前端改→DB→后端只读，**无第三层**（代码禁存提示词常量、禁"DB 空则代码兜底"）；③规则统一存策略中心-需求分析，千万不可写在代码里；④工具绑定统一在 Skill Studio 节点抽屉（工具实现属代码、启用/绑定属配置）；⑤节点只留接口：agent_fill 换目标层表格+换数据/规则/工具即可复用到其他 skill——复用成立才是接口做对的证明。

**树干-枝叶模型**：树干（代码机制）=六节点编排、大脑回合（make_fill_brain）、确定性校验/缺口协议、工具执行 registry、节点接口契约本身。枝叶（DB 数据）=提示词/AI层（skill_prompt_template+reasoning_node_default+画布 description，已达标）、规则（策略中心，**缺位**，规则页需用户单独设计后再接入）、工具绑定（enabled_tools，达标）、数据（业务表+data_boundary，达标）、目标层（画布配置+requirement_slots，达标）。

**节点五插槽契约**：①目标层（输出表 schema，fill_requirement 参数已按此动态生成）②AI 层指令 ③资源层绑定 ④执行机制声明（确定性 or 大脑回合）⑤上下游数据协议（登记表快照只进不出）。验收场景：录一条规则/换一张目标表，不碰代码生效。

**目标层输出物插座（09-02 晚 v2，agent_fill 样板）**：node config `target.artifacts[]` 描述符（name/kind: form|document|media/schema_ref/view）驱动抽屉**输出物卡片列表**——大表不塞抽屉，点卡片进 **TargetLayerModal**（860px）。**v2 重做（用户痛批 v1 敷衍后）**：预览与编辑必须同一份 schema 数据驱动（v-show 切换不销毁、禁异步组件+fromSlots 时序坑），结构复刻真实线索登记表三区（需求原文/配置字段/部件清单 KP 大类只读行）；字段行内联编辑（中文名/必填开关/候选来源/排序删除）+反问阈值；**KP 大类映射 UI 移除**（后端继续消费 DB 默认映射，编辑器不再展示两张皮）；SlotListEditor 已删除；schema 标签/顺序已对齐真实表单（机型型号/平台类型/服务器类型/机箱形态/数量/维保年限，数据修正）。用户裁定：聊天侧不要查看详情（TaskStepper 纯展示，两面板已卸 NodeArtifactModal）；prompt 必填投影是假样式不做。**长期统一方向（待办）**：商机详情页 RequirementForm 字段写死，未来让它也消费 requirement_slots schema 才能彻底根除"配置表与真实页两张皮"。
