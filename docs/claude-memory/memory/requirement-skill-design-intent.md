需求分析（用户 2026-09-12 定调：**已从 skill 变为 workflow**，6步链：输入→需求分析→机型选型→配件选配→BOM组装→输出；AI 办公室能力库时代 2026-08-20 首定）：

0. **架构心智模型（09-12 二次定调，最关键）**：**AI角色=唯一大脑**，workflow 不是驱动器、是指引——告诉 AI 该走哪些步骤、每步输出什么给下游；步进闸门只是护栏（检查目标表填好才放行），不决定怎么干。AI 是同一个"人"先后扮演两个业务角色（先线索登记员、后方案配置技术员），**交接靠表**。跨步骤传递的信息必须进表、不能只活在聊天里（技术员只认单据）——这条是 workflow 验收标准；下游若依赖聊天独有信息，是登记表漏字段不是模型错。
1. 人工流程基线 = 商机详情页四步：线索登记 → 方案配置 → 成本核算 → 报价单
2. workflow 范围 = 走到**方案配置**这一步为止（不做成本核算/报价单）；**映射**：agent_fill=线索登记、机型选配+配件选配=方案配置，目标输出物就是这两步对应的商机详情页真实表格
3. **AI = 配置器**：读需求→决定配什么→去库找→填进目标输出表。哪怕线索登记只有一句模糊话（"要台AMD平台的通用计算服务器"），配件选配也要给出配置
4. 最终产物 = 商机详情页「方案配置」环节配置完成待提交的那个网页配置表（portal bom-scheme 的 configs/PortalSheetConfig 结构），不是聊天里的文本方案
5. **节点抽屉两层**：①目标层=目标输出物（表格/文档/PPT），表格设计=左字段右预览+字段可勾「必填反问」（AI 分析不出必问用户）；同时承担向下游传数据。②资源与权限层=数据（系统内部，不许编）+工具（skill 执行期自动放开，不要求角色绑定）+规则（服务器怎么配：兆芯→Polaris/AMD→Orion，底座入口=策略中心-需求分析，慢慢补充）+（我提议中）LLM 算力档
6. **提问由 AI 按上下文+节点目标组织，禁止硬编码话术写死在节点里**；模糊需求=AI 用自身知识抓重点选择性问（AI服务器重点问GPU，别全字段问一遍）；清晰需求=规格查库，查不到→按性能推荐近似件给用户选
7. 线索登记表登记完后下游不回填——**业务表所有权的天然属性**，非代码锁（下游目标物是另一张表，大脑照 workflow 干活自然不越界）
8. 建设期策略=先设计主干"插座"再做"插头"（数据/工具/规则都可后补，系统先跑通）

**Why:** 09-12 用户给出设计原文并两次纠偏（skill→workflow；AI唯一大脑+workflow仅指引）。对照现状：6节点链/必填反问/工具自动放开/模糊清晰两分支已落地；规则运行时已活(system_config)但策略中心-需求分析编辑页未建。
**How to apply:** 碰需求分析 workflow 的输出格式、执行链、验收标准时，以「等价于人工在方案配置页点提交前的状态」为准；提速类改动挂**节点资源层 LLM 档位**（表格即接口→步骤边界是换模型天然接缝，agent_fill 轻/kp_reason 重；卡挂起时同一大脑可后台预跑下游），不动树干、不引入第二大脑。相关：[[opportunity-detail-intel]]、[[agent-understand-pure-llm]]、[[skill-tree-trunk-architecture]]、[[inferred-slots-must-confirm]]、[[agent-architecture-decision]]。
