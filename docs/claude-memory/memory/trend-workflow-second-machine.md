# trend_analysis 修通：第二台机器第一次插上插座（2026-09-15）

需求分析之外第一个 workflow（trend_analysis，output_kind=data_answer）已全链路可用：AI 办公室「+」发起 → agent 节点跑 LLM+query_data → data_answer 闸门 → 结论直接落对话（无 BOM 卡）→ mission 记账带 data_answer artifact。生产探针实测两轮（交付+交付后再发起）均正确。同日晚追加 **PDF 报告产物链**（生产验证过：171KB 报告落会话文件卡+任务看板可下载）。

**Why:** 原审计实锤四层断裂（skill_key 进不了引擎/DB 节点无配置/final_gate 硬编码机型锁/done 收尾硬编码 BOM 广播），修复原则=需求分析路径逐字节不变（368s e2e 承重），一切分派按 `output_kind=="data_answer"`/skill_key 走新分支。修完后 e2e 回归 183~185s 通过、727 测试过。

**How to apply:**
- 新增 workflow 型 skill 的接线点：DB flow 的 output 节点配 `output_kind`+`payload_map`；agent 节点配 `enabled_tools`；DELIVERY_GATES 注册表（skill_plan_runtime）按 output_kind 注册终检；colleague_turn_runners done 分支按 output_kind 分派收尾。别再往 requirement 专用代码里加 if。
- **生产验证追加修的四 bug（都是通用陷阱，加第三个流前必看）**：
  1. skill_chat 回存 mem 必须带 `engine_result`——data_answer 型流没有 compose 步，不存的话 flow_delivered 恒 False，交付后下一条消息误入旧分支。
  2. 流程记忆必须**盖章 skill_key**（_prepare 恢复时比对，不同流→重置）：steps_done 的键（agent/compose）跨流同名，旧流的 done 会把新流的同名步骤跳掉（实测：零大脑步直落终检、僵尸 gap 循环）。
  3. `_skill_chat_memory_active` 只认「无 skill_session 字段」的记忆——原谓词 `bool(mem)` 会把任何带会话残留的线程劫持进硬编码需求分析分支。
  4. `finalize_output` 返回值是 handoff **信封**（payload 嵌在 .payload），真 payload 由它内部写 `ctx["output_payload"]`——绝不能拿返回值覆盖 ctx。单测挂 `event_sink=None` 会掩盖此 bug（广播抛异常→except 跳过覆盖行），测交付必须挂真 sink。
- **PDF 报告产物链（09-15 晚，兑现「输出节点目标输出物多格式」）**：输出节点 `artifacts=[{kind:document,format:pdf,title}]` 插槽（抽屉开关+格式+标题，buildConfig 写 config.artifacts）→ `skill_node_runtime._render_file_artifacts`（确定性 reportlab 渲染 markdown→PDF，失败不挡交付）→ `report_pdf.py`（中文字体链 REPORT_PDF_FONT→msyh.ttc→STSong-Light 兜底）→ `storage_adapter.save_scoped` 落 `storage/office/reports/`（office 中立桶，不进商机附件体系）→ `GET /api/office/reports/{oid}/download`（鉴权双通道：Authorization 头 或 `?token=`）→ 会话 kind=file 文件卡（AssistantPanel，utils/fileDownload.ts blob 下载/iframe 预览）+ 任务看板 pdf_report artifact。任何 data_answer 流开开关即得，渲染器不认识具体流。
- **agent 步迭代耗尽=同流僵尸循环（09-15 晚实测）**：冷启动大脑把 6 轮迭代全花在 information_schema 探索上，没来得及写结论 → steps_done 记了 agent 但 agent_result.answer 为空 → 续跑跳过 agent 永远补不出结论（gap 循环，大脑还复读「请用+发起」）。处置=trend flow agent max_iterations 6→9 + 清线程流程记忆干净重跑（workflow_launcher 入口）即过。根治（让续跑在 answer 空时重开 agent）未做，加流/调迭代时记得这个坑。
- **目标层 document 插头通电（09-16，报告结构数据化的兑现）**：根因=趋势流 manual_rules 全空+agent 节点零 target，报告结构靠 LLM 即兴（不是硬编码，是没喂）。三层落地：① seed 脚本 `scripts/seed_trend_flow_target_20260916.py` 播 manual_rules 5 条（含数据源线索：opportunities 无 platform 列，平台/机箱从 quotations.config_server_models 推导，禁止拿 status 充当业务维度）+ agent 节点 target.artifacts=document 七节；② 注册表三件套：`skill_target_contract._CONTRACT_FORMATTERS["document"]`（format_document_contract，章节「一、二、」中文序号）+ `skill_node_artifacts.BUILDERS["data_report"]` + NodeArtifactModal kind=document 分支（MarkdownContent 渲染，prop 名是 `source`）；③ 抽屉目标层泛化到 agent 节点。**数据范围可配**：artifact.data_range（auto/last_30/last_90/half_year/this_year/custom），后端 `_report_window` 确定性算窗写进契约（大脑不得越窗统计），前端弹窗 JS 镜像预览。章节编辑=BOM 模板编辑器同款 vuedraggable 拖拽行（handle ⠿ + grid 表行）。生产探针九断言全过（1748 字七节+PDF 卡）。同日删 agent 节点 system_prompt 死控件（引擎人设恒非空，兜底走不到）——指令唯一出处=左栏 manual_rules。
- **数据口径事故（09-16）：ai_office 壳商机污染统计 + 维度口径全错**。两次用户实测打回：①统计失真（9月242条/admin 265），根因=opportunities.opportunities 混三种 status：ai_office=AI 会话自动建的壳（307条）、deleted=46、active=真实仅168。商机线索页口径（opportunity_repo.list_opportunities）= status NOT IN ('ai_office','deleted')。②平台/机箱维度错乱（Z 系列/ES 系列=机型名前缀推导、Key Parts/L6=part_category 冒充机箱）。**权威口径（DB 实证）= opportunity_requirements.slots（json 列，status='current'，opportunity_id 关联）**：slots->>'platform_type' 取值 Orion/Polaris/Intel/工作站（近半年 76/50/7/2，与用户案例 88/57/9/2 同排序同量级）、slots->>'chassis_form' 取值 4U/2U/5U/工作站/4.5U/8U（66/58/…），按商机数统计，覆盖 135/168（缺的标「未填写」）；extra_fields 里没有这两个键。修复=manual_rules 第2条写死唯一口径 + 第6条交付纪律（答复=报告本身，首行「数据范围：」，禁开场白/工具备注——此前「收到，继续补齐…」混进了报告和 PDF）。**白名单错觉**：jsonb_each_text 写进 FROM/JOIN 被 _FROM_JOIN_RE 当表名拦截，报错像「函数不在白名单」，但 `->>`/`->` 运算符语法合法——教大脑用运算符别用函数。created_at 是字符串列（::timestamp）。**窗口改算事故（同日）**：配置 custom 2026.01.01~09.12 契约渲染正确，大脑却用数据边界（首条商机03.06~最新09.15）自行改算数据范围+全量统计。**根因=对话历史锚定，不是链路**：试运行每轮独立新线程（正常），真实聊线程里躺着连续多份旧窗口报告，大脑复读自己上次的输出——提示词（契约加硬+manual_rules权威条款）压不住。**根治=确定性终检** `_data_answer_gate`：交付前比对报告首部与 document 目标层配置窗口（`_report_window`），不符即拦截 + reopen 该节点（steps_done 摘除，pause 载荷在摘除后快照故续跑真重跑）。同日用户铁律：禁令文字撤出 formatter，契约只陈述形状（纪律见 [[feedback-no-instructions-in-code]]）。**同日晚用户二次定调：出口拦截+重试太粗糙（若再错则恶性循环）——根治必须在入口**：`_build_step_call` 里 document 产物节点（target.artifacts 含 kind=document，插座属性非流特判）组上下文时确定性剔除「报告形状」的历史 assistant 消息（指纹=「数据范围：」，契约规定的报告首行）——旧报告在生成上下文里是纯毒药（锚定源+数字过期），闸门降级为永不触发的保险丝。教训：治理 LLM 复读，先问「污染从哪个输入进来」，别先在出口装探照灯。凡把窗口/口径交给大脑执行的场景，必须有确定性闸门兜底，提示词只作第一道。凡让 AI 统计业务表的场景，先对齐页面口径再给大脑写规则。**draft 回退口径（09-16 第三发）**：教大脑 strict `r.status='current'` 后用户实测本周平台全「未填写」——线索页 `_current_slot_map` 语义=current 优先、**slots 整体为空才回退最新 draft**（快速录入/AI 路径的需求单全是 draft）；配置数口径=每商机只取 `status='active'` 最大 version 那条报价单的 `config_count` 求和（行数≠配置数：大脑数行数得 7，正确 9）。修法=manual_rules 第2条内嵌 `LEFT JOIN LATERAL(...status IN ('current','draft')...
