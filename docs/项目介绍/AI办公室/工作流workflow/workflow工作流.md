## 1 为什么做？让 AI 学会做配置方案
功能的起点很简单：我想用 AI 自动生成服务器配置方案，作为把AI的能力引入CPQ报价系统的第一站。

面向装备、汽车、服务器这类选配、BOM生成场景，行业内已经有成熟的路线。在AI大模型兴起之前，一般是通过产品配置器选配，提前把所有配件的兼容、互斥规则录入系统，形成配置约束引擎。前端给用户一个向导式选配页面，用户一步步选参数，配置引擎则实时根据底层校验规则自动拦住不能选的组合，返回合规配件，比如选了兆芯平台的服务器机头后，后面不兼容的配件选项直接置灰、不可勾选。

AI时代，这类产品正被重构，过去的操作流程就像：
[用户需求] -> [人理解需求，信息不足或不确定时向用户发问] -> [根据需求操作配置器选配，过程中自主思考下一步选什么] -> [选型配置器做合规校验] -> [完成方案配置，做配置表] -> [输出给用户]

而 AI 特点是在自然语言理解上优势突出，在需求理解阶段它可以承接用户口语化、碎片化的需求描述，拆解出平台、性能、预算等关键约束，补齐缺失参数并主动确认模糊信息。但 AI 本身并不擅长保证硬件选配的合规性，所以选配过程不能简单的用提示词+skill+配置规则的组合完成，因为AI是概率生成模型，不是确定性执行引擎，随着会话越长、规则越多，AI对用户输入内容的遵循概率会越来越低。而skill本质上是描述详尽的增强版的提示词，他可以引导AI做事，但不是强制约束，躲不过AI上下文长了生成的内容就漂移的问题。skill 形态解决的是「让模型知道更多」，我们需要的却是「让业务产出更可靠」——前者我们用说明书就能做到，后者必须靠工作流，尤其是服务器配置涉及真实物料，价格和配置规则，需要可控、无幻觉。

所以需要将服务器方案配置过程用Workflow编排引擎固定下来，将每一步要完成的目标，需要遵循的规则和输出物都做好配置。大模型把自然语言需求转化为结构化选型参数，再交由底层配置约束引擎物料匹配、互斥兼容判断（例如选定兆芯平台机头后，不兼容的主板、电源、扩展卡等配件自动置灰屏蔽），配置约束引擎返回合规候选集之后，大模型再基于成本、交付周期、客户偏好做择优组合、输出方案配置，所以AI时代，新的操作流程变为：
[输入用户需求] -> [AI理解需求，信息不足或不确定时向用户发问] -> [AI一手拿着用户需求，一手操作机型选型] -> [配件选配] -> [组成配置单] -> [输出]

在这个模式下，大模型承接开放、灵活的自然语言交互，发挥它擅长理解五花八门客户需求的优势；Workflow 守住流程秩序，防止对话过程跑偏、状态丢失；产品配置器守住硬件兼容这条底线，杜绝幻觉带来的物料错配，输出符合标准的配置方案。

## 2 怎么做？AI唯一大脑 + 确定性工作流 + 插头插座设计 + 闸门

选定workflow模式后，就该思考怎么设计工作流，在CPQ系统中，人出方案涉及两个环节：业务在线索登记节点填写填写线索登记表；FAE在方案配置节点出配置方案，具体而言就是先选机型，再选配件这两步，完成方案配置表。

所以我的思路是模仿人出方案的步骤，按以下节点编排工作流：
[需求分析] -> [机型选型] -> [配件选配] -> [方案组装] 

节点每一步都要有确定性的输出物，且这个输出物要对应CPQ系统中的真实表格。AI需要在需求分析节点填写线索登记表，填好后传递给下游节点；下游节点根据线索登记表，在机型选型节点选定L6机箱，填写方案配置表中的机箱部分，把机箱表传给下游；配件选配节点拿到机箱表，根据平台去配件库里拿适配需求和机箱平台的配件，填写方案配置表中的配件部分；方案组装节点把机箱表和配件表拼起来，组成符合要求的方案配置表。

流程中AI角色是唯一大脑，为什么强调「唯一大脑」？因为最开始我是在每个节点里单独写了一个说明，本意是告诉AI你在该节点要做哪些事情，做完后把做的产出物传递给下游节点，下游再拿着上游的产出物和自己的节点说明处理任务。

但在具体执行中，变成了每个节点都是一个单独的大脑。AI在需求分析节点，读节点说明，起了一个会话，当完成该节点任务后，就把这个会话关闭了，留了个产出物给下游节点，下游节点又起一个会话，读当前节点要做的事情，但这时候就已经丢了不少上下文了，不仅导致配出来的内容有问题，还导致极其耗时。像厨房里做菜，变成一个节点一个师傅，洗菜切菜一个、起锅烧油一个、调味一个，看起来分工明确，但做出来的菜就不是一个味了。

所以随后我改为在AI开始执行工作流前，先给他一段类似skill的说明，告诉AI角色，你要做什么菜，应该走哪些流程做事情，每一步要遵循什么规则、会用到哪些工具、目标输出物是什么。由于对应的是真实业务节点的表，所以对齐真实业务节点规则，那就是下游不能修改上游节点的内容，比如线索登记表填完，到下游就只能拿他做参考，不允许篡改上游的内容。然后再开始逐个节点跑工作流。每个工作流节点都有节点抽屉，节点抽屉有两层：

1 目标层：节点的目标输出物，可以是表格、文档、PPT甚至是图片。这一层同时也承担输出给下游的数据，下游拿到上游节点的输出物后开始工作。目标层典型的输出物是表格，表格输出物的设计是左侧是字段，右侧是表格预览，字段可勾选是否必填反问，如果勾选，那AI角色必须填这个字段，分析不出来的时候一定要反问用户。

2 资源与权限层：包括可调用的工具，需要遵守的规则。

中间有缺的字段AI会提问，提问内容是AI角色根据上下文需要，以及节点目标输出物组织的。在任务跑起来后，会话窗口会显示流程步骤，节点画布上会高亮显示正在执行的节点，节点会实时显示目标输出物的填写进度，填写完成后，用户可点击查看该输出物，让每一步都可追溯。

2.2 工具：比如有哪些机箱可以选，去机箱目录里拿数据，有哪些配件可以选，去配件库拿。去拿这些数据，肯定不能直接把大量数据灌给AI角色，因此设计了工具来解决。AI角色可以调用哪些工具，因为每个AI角色自身是绑定了工具的，但skill是公用的，也就是说可以配给任何一个AI角色，但这个AI角色不一定有这个skill层里涉及的每一个工具，所以这时候会在任务进行过程中，只要绑定了这个skill的角色，在任务几个步骤推进过程中，就自动可以使用那个工具，即使AI角色本身没绑定这个工具。

2.3 规则：系统主要功能是服务器配置，规则层是告诉AI角色，服务器怎么配，比如根据CPU决定机箱平台，当用户选择兆芯系列芯片时，机箱就得选Polaris的，当用户选择AMD系列芯片时，机箱就得选Orion系列的，等等，这一点需要慢慢补充，当然这个前提是搭好底座，规则底座入口就在策略中心-需求分析里。

系统处于建设阶段的时候，数据、工具、规则，都是不完整的，因此我们需要先设计好主干“插座”，然后再做插头，插头可以后补，重要的是系统先跑通。
