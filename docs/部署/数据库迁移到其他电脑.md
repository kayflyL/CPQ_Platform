# 数据库迁移到其他电脑（换机部署）

> 最后更新：2026-08-02

## 背景

本仓库是**单机应用**：代码在 git 里，但数据库（PostgreSQL `cpq_platform`，6 个 schema / 52 张表 / 约 14 MB）不在。仓库里没有建库脚本，`backend/migrations/` 全是增量 `ALTER`，`Base.metadata.create_all` 只覆盖一小部分 ORM 表。所以**换台电脑跑，必须手动把数据库搬过去**——光 `git clone` 不够。

搬家分两步：**源机导出**一个 dump 文件 → **目标机恢复**。仓库根目录的 `restore_db.bat` 已把「目标机恢复」做成一键脚本。

> 单库多 schema：`kp` / `l6` / `opportunities` / `rules` / `l6_history` / `parts`（`parts` 当前空表）。`pg_dump` 整库一次性全带走。

---

## 一、源机：导出数据库

> 若 `D:\cpq_platform.dump` 已存在且数据是最新的，可跳过本节，直接拿去目标机。

```bash
export PGPASSWORD=源机postgres密码          # Git Bash；cmd 用 set PGPASSWORD=...
"/c/Program Files/PostgreSQL/18/bin/pg_dump.exe" \
    -U postgres -Fc -d cpq_platform -f D:\cpq_platform.dump
```

- `-Fc`：custom 压缩格式（14 MB → 约 290 KB），配合 `pg_restore` 恢复。
- 导全库：schema + 表 + 序列 + 数据，一次齐活。
- 路径里的 `18` 按本机 PostgreSQL 大版本改。

---

## 二、目标机：恢复与运行（6 步）

### 1. 安装 PostgreSQL 18 或更高 ⚠️

dump 由 **PostgreSQL 18.4** 导出，目标机**必须 ≥ 18**。`pg_restore` 不能降级读新版本的 dump，装 16/17 大概率恢复失败。

下载：<https://www.postgresql.org/download/windows/>

### 2. 拉取代码

```bash
git clone <仓库地址>
cd CPQ_Platform_V1
```

### 3. 单独拷贝 dump 文件到目标机

把 `cpq_platform.dump` 拷到**仓库根目录**（与 `restore_db.bat` 同级）最省事。

> ⚠️ dump 文件**不在 git 里**（仓库外、含真实数据）。clone 代码拿不到它，必须手动拷（U 盘 / 网盘 / 内网）。

### 4. 双击 `restore_db.bat` 恢复数据库

按提示输入目标机的 postgres 密码即可。脚本会自动：

- 探测 PostgreSQL 安装路径（找不到可用环境变量 `PG_BINDIR` 覆盖）；
- 检查 `cpq_platform` 是否已存在，**已存在则拒绝覆盖**（避免污染，需先手动 `DROP DATABASE` 再跑）；
- 建空库 → `pg_restore` 恢复 schema + 数据。

> 也支持**把 dump 文件拖到 `restore_db.bat` 图标上**直接运行（不必放同目录）。

### 5. 安装依赖

```bash
cd backend  &&  pip install -r requirements.txt
cd ../frontend  &&  npm install
```

### 6. 启动

双击仓库根目录的 **`一键启动.bat`**（会同时起后端 + 前端 + 打开浏览器）。

或手动：
```bash
# 后端（Windows 必须 -X utf8）
cd backend && python -X utf8 -m uvicorn app.main:app --reload --port 8000
# 前端
cd frontend && npm run dev
```

首次启动时 `startup.py` 会自愈字段、灌默认规则（推理流 / 兼容性规则 / 系统配置等）。

## 三、纯命令行版（不依赖 .bat）

适用于 Linux/Mac，或想手动控制每一步的场景。

```bash
export PGPASSWORD=目标机postgres密码
# 1) 建空库
psql -U postgres -c "CREATE DATABASE cpq_platform"
# 2) 恢复
pg_restore -U postgres -d cpq_platform --no-owner --no-privileges cpq_platform.dump
```

`--no-owner --no-privileges`：跨机器恢复标准选项，忽略原库 owner/权限，避免因用户名不一致报错。

> Linux/Mac 用包管理器装 PostgreSQL 18：`apt install postgresql-18` / `brew install postgresql@18`，装完 `psql`/`pg_restore` 直接在 PATH 里，命令去掉全路径即可。

## 四、连接配置

后端通过 `backend/app/core/config.py` 连库，默认 `postgres@localhost:5432/cpq_platform`。**目标机 postgres 密码若与默认不同**，在 `backend/` 下建 `.env`（此文件被 gitignore，不会进仓库）：

```ini
POSTGRES_PASSWORD=目标机密码
# 用 AI 功能还需：
LLM_API_KEY=你的key
LLM_MODEL=qwen-plus
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
```

## 五、常见问题

| 现象 | 原因 / 解决 |
|------|------|
| `pg_restore` 报版本相关错误 | 目标 PostgreSQL 低于 18。dump 由 18.4 导出，必须 ≥ 18。 |
| `extension` 字样报错 | dump 引用了目标机没装的扩展。先进库 `CREATE EXTENSION xxx;` 再重跑恢复。 |
| `database cpq_platform already exists` | 库已存在，脚本不自动覆盖。先 `psql -U postgres -c "DROP DATABASE cpq_platform"` 再恢复。 |
| 连不上数据库 / 密码错误 | 确认 PostgreSQL 服务已启动、密码正确（`.env` 的 `POSTGRES_PASSWORD`）。 |
| 中文乱码 | 后端启动必须带 `-X utf8`（Windows）；库连接已强制 `client_encoding=UTF8`。 |
| 换机后数据是空的 | dump 没拷过来 / 恢复到了别的库。核对 `l6.parts_master` 行数（应为非零）。 |

### 数据脱敏（要给外部时）

`cpq_platform.dump` 是**全量真实数据**（料号价格、KP 配件价、客户名都在里面）。给外部或放公网前，不要用全量 dump，改导**空结构**再手工挑演示数据：

```bash
pg_dump -U postgres -Fc --schema-only -d cpq_platform -f cpq_platform_schema_only.dump
```

### 安全提醒

`config.py` 把数据库密码写成了默认值。若仓库公开，建议改为读 `.env` 必填、移除硬编码默认，避免凭据随代码泄露。
