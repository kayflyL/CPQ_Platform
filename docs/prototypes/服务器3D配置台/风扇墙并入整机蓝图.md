# 风扇墙并入整机蓝图（2026-11-06）

> 定调出处：会话讨论「整机风扇墙单排→部件库两行模块替换」。
> 范围：**只换整机风扇墙**。剖切/透视不在本轮；悬停语义整机保持整区一张卡（用户拍板，不做子件细分）。

## 1. 目标与问题

现状 `machine.ts` 风扇墙：12 只单排圆柱示意扇（r=0.17），单排总宽 4.74 单位 **已超机身宽 W=4.6**，且造型精度远低于部件库 `parts/fan.ts`（2×6 八角框模块）。

目标：整机的 12 只风扇换成部件库同款单扇模块（6列×2行），halo 霓虹环保留。

## 2. 模块抽取契约（闸3 落地物）

`parts/fan.ts` 导出公共单扇模块工厂：

```ts
export interface FanModuleMats { frame: Material; rotor: Material; hub: Material; sticker: Material; screw: Material }
export function createFanModule(mats: FanModuleMats): { g: THREE.Group; rotor: THREE.Group }
// g: mm 域单扇(八角框+四角螺丝+规格贴纸+转子组), userData 语义键已挂
// rotor: 转子组引用(调用方驱动常转/爆炸停转)
```

- 材质由调用方注入（部件页一组、整机一组），**禁止每扇新建材质**（整机「少材质」纪律）。
- `createFanModel` 内部改为消费该工厂（护罩板/提手/金手指是墙级构件，留在 createFanModel）。

## 3. 整机侧布局账（mm→machine 单位）

| 量 | 值 |
|---|---|
| 单扇模块 | 8038（80×80×38mm，fan.ts 原值） |
| mm→整机单位系数 | 0.00825（80mm→0.66 单位直径） |
| 列×行 | 6×2（cfg.fans=12 不变；cfg.fans 变化时按 ceil(n/6) 行自适应） |
| 墙宽 | 6×0.6765 ≈ 4.06（机身 4.6，两侧余 0.27 ✅ 修掉旧溢出） |
| 墙高 | 2×0.6765 ≈ 1.35（机身 H=1.78，中心 y=H×0.52 ✅） |
| z 位置 | D×0.245 ≈ 1.76（不动，风扇在硬盘笼与 CPU 区之间的风道位） |

## 4. 发光不丢——halo 上移为整机装饰层

- halo torus（M.cyan + tagGlow('fans')）**保留在 machine.ts**，每扇一环，套在模块前缘；部件库页不带 halo。
- 材质天然兼容：模块是 MeshPhysicalMaterial 不自动进 bloom 层（不炸白），halo 是 BasicMaterial 自动进 bloom 层。选择性 bloom 机制零改动。

## 5. 主题

- machine.ts 新增 `applyTheme(t, name)` 钩子（StageModel 契约本就支持可选）：先做现 M 袋换色（与 stage 回退逻辑同式），再按 `FAN_THEME[name]` 换风扇模块三色（frame/rotor/hub+sticker）。
- 风扇模块深色塑胶在浅色主题下保留（真实服务器即黑色塑胶），只按 FAN_THEME.light 提亮防糊白——与部件页同一套色表。

## 6. 语义与文案

- 整机悬停仍是整区一张卡（resolveKey 不动）。
- `machine.ts` PART_INFO.fans 文案更新：'8038 热插拔风扇墙 · 6列×2行'（原 '6056'）。

## 7. 触点清单（闸3）

## 8. 不做清单

- 剖切/透视（下一轮独立闸项）
- 悬停子件细分（用户拍板整区一张卡）
- cfg.fans 动态数量的精细边界（先支持 12=6×2 自适应行数即可）

## 9. 硬坑对照

- 闸2 原型必须亲眼截到新帧（?snap=1 canvas→img 覆盖层，防后台 rAF 节流假帧）。

- 转子引用经模块工厂返回，fanSpinners 改存模块 rotor 组。
