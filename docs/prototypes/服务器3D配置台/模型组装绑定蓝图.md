# 模型组装绑定蓝图 · 第二轮（2026-11-06）

> 定调出处：会话拍板——绑定选择权交给用户，不在黑盒里自动配；服务器模型分裂成多行，各带悬停文案。

## 1. 数据契约（layout_config 扩展，后端仍整存整取不透明 JSON）

```json
{
  "labels": { ...分区标注覆盖,机制现成... },
  "machine": { "cpu_part_id": 4 }   // 绑定部件库哪一行(引用,非复制);缺省=不绑定→默认 AMD(sp5)
}
```

- family 从被引用部件行的 `layout_config.family` 读——部件行保持纯资产登记，绑定权威在服务器模型行。
- 兼容：老行无 machine 键 = 默认 sp5，无痛。
- **拆除黑盒**：ConfigWizard 的 `series.includes('兆芯')` 映射删除，改为 机型→绑定行→行配置→部件行 family。

## 2. 复制（分裂）机制

- repo 加 `create()`；后端加 `POST /api/server-3d-models/`（page.settings.admin 同门）。
- 前端 server3dApi.create；管理目录页行操作加「复制」：名称+" · 副本"，layout_config/kind/part_type 原样带，**model_ids 清空**（新行不自动上架，用户自行改配置后把机型挪过来）。

## 3. UI（模型页管理浮窗，沿用设置卡范式）

- 整机行（kind=machine）管理浮窗加「3D 组装」小节：处理器部件下拉（不绑定=默认 AMD + 部件库 cpu 行列表，label=行名）。
- 选择即改草稿，保存时并入 layout_config（load 时保留原始 lc 其余键做合并，不再丢弃未知键）。
- 画布预览实时反映绑定（cpu-family prop 既有 watch 重建机制）。
