AI 办公室 · 手机版优化方案

> 最后更新：2026-09-19 · 原型稿（仅视觉示意，非实现）

桌面结构 = 顶部团队/管理 + 三栏（左任务看板 ｜ 中 3D 办公室 ｜ 右同事检查器=聊天） + 三个全屏弹层（团队管理/日志审批/任务看板）， 现有手机处理只是竖排长页。这页的主场景是「在场感 + 找人聊」，方案： 3D 办公室独占全屏；底部 sticky 条 = 同事头像横滑行（点人即聊）+ 任务按钮；点同事 → 底部升起全屏聊天层；左抽屉 = 任务看板；管理/日志收进 ⋯。 四张手机框：A 主屏 / B 全屏聊天层 / C 左抽屉·任务看板 / D 对比与分期。

现状诊断

  • 竖排堆叠毁掉在场感：≤860px 现有处理只是把三栏叠起来，3D 变 460px 小窗，上下滚动后方位感全失。
  • 聊天被压扁：检查器（聊天所在）垫底，输入框在键盘弹出时几乎不可用。
  • 找人成本高：必须在 3D 里精准点中一个小人；任务看板与预览卡两套并存。

分期落地

P1容器重构（≤860px 分支改造）：3D 全屏 + 底部同事头像行 + 任务按钮 + 左抽屉任务看板 + 全屏聊天层；⋯ 菜单收纳管理入口；桌面三栏零改动。
P2体验细节：聊天层从底部滑入动画；头像行选中高亮与 3D 中同事高亮联动；任务进行中数实时（WS 已有）。
P3打磨（可选）：点 3D 同事时相机推近动画；聊天层内快捷动作（发起任务/查看该同事日志）；团队切换下拉底部化。

代价与取舍

  • 3D 交互是首要风险：触摸拖拽/缩放/点选 raycast 需在真机验证，这是 P1 第一件事；若点选不准则头像行兜底。
  • 管理动作多一步：Manage Teams/日志审批收进 ⋯——低频管理动作，可接受。
  • 收获：办公室从「长页里的装饰」变回「可逛可聊的现场」；与全站四页共享「主内容独占 + 旁路抽屉 + 拇指区动作」语言。

与全站手机版语言的一致性

  • 主内容独占：这页主内容 = 3D 现场（线索页=驾驶舱、详情页=工作台、配置向导=配置卡、报价台=编辑区）。
  • 旁路抽屉：任务看板进左抽屉；高频身份/动作进拇指区（头像行替代静态摘要条）。
  • 组件零改动：3D 画布 / 聊天面板 / 任务看板 / 管理与治理面板全部原样复用。
