中间层 —— AI 与 CPQ 之间的「翻译 + 插头」

AI 办公室（引擎）只懂自己的语言：工具、闸、审计。CPQ 只懂自己的语言：服务函数、表单、数据库。 让两边说上话的，是中间层——它把 CPQ 的能力翻译成引擎协议里的工具，把引擎的规矩翻译成 CPQ 能执行的调用。 下面用最普通的一件事，把整条链走一遍。

一次「查配件价格」的完整旅程

销售对 AI 说：「64G 内存什么价？」——从这句话到价格出现，一共六跳，每一跳的负责人不同。
1
引擎 · AI 办公室 听懂意图，决定用什么工具
销售：「64G 内存什么价？」
引擎的工具循环翻说明书（中间层给的清单），选中工具 查配件；工具不在清单里 = AI 根本不知道有这个能力。
2
引擎 · 四道闸放行 检查这一步的规矩
查价格是只读 → 免确认直接过；价格可见性按你的权限裁决（无授权者看不到价，fail-closed）；这一笔同时记入审计账本。
3
中间层 · 按声明找到"怎么查" 说明书翻到这一页
工具清单（中间层）写着：查配件 的名字、参数、确认级别，以及——去哪查：适配器 配件查询适配器。声明与"怎么查"都住在中间层。
4
中间层 · 适配器真正出手 把 AI 的问法翻译成 CPQ 的调用
适配器把「64G 内存」翻译成 CPQ 听得懂的调用：按名称查配件（类别=内存，关键字=64G，价格权限=你的权限）——这是进程内函数调用，调的是 CPQ 自己的检索服务；结果压缩成 AI 读得懂的摘要。
5
原网站 · CPQ 真正执行 服务函数查库，按权限过滤
CPQ 的检索服务查配件主数据表 → 按你的角色过滤价格可见性（没授权的行连价格一起藏掉）→ 返回候选行。规则本体（哪些价格谁能看）全在 CPQ，中间层和引擎都只是转达。
6
引擎 · 结果交还大脑 AI 拿到摘要，用人话复述
「64G DDR5 5600，单价 1,800 元」——整个过程中引擎没查过一次库、中间层没做过一个业务决定、CPQ 不知道 AI 的存在：三层各干各的。
写入类操作（比如改价）走同一条链，只是在第 2 跳会插一道确认卡：你点了才放行，放行后系统回头查库核对，并把这笔账记进审计。

这条链上的每一环，归谁所有

你说"连工具、工作流都要拆出来"——对，但要拆得准：拆的是源码所有权（谁写、谁审、放哪个包），不是进程。适配器代码运行时仍在引擎进程里被调用（像浏览器扩展装在浏览器里跑，不是独立软件）。

「按协议写好的中间层」长什么样

协议已经存在（ABI：事件分册一 / 工具分册三 / 宿主接口分册四）。中间层 = 照协议写成的一个可装载的包；引擎装它，就像系统装一个程序包。今天缺的不是协议，是包的"插槽"自动发现（G1）。
app/cpq/ ← CPQ 的接入包（源码在 CPQ 仓库，随 CPQ 一起版本化） ├─ app.json ← 包描述：名字、版本、依赖（引擎扫到它=发现插头） ├─ tools/ ← 功能清单 + 适配器（声明与"怎么查"同住） │ ├─ delivery_quotation.py 已迁 ✓ │ ├─ requirement.py 已迁 ✓ │ └─ adapters.py G2：适配器从引擎侧搬进来 ├─ flows/ ← 工作流源：步骤/目标层/规则/数据层声明 │ ├─ delivery_to_quotation.json G3：源从引擎数据库归位到包 │ ├─ requirement_analysis.json │ └─ probes.py G4：探针填表化（数据层声明） ├─ forms.py ← 表单源声明（登记表 ← 商机表单配置） ├─ builders.py G5：产物插座注册（刀一） ├─ rules.md ← 左栏纪律（注入大脑的规则文本源） └─ ledger.md ← 写面台账（开了哪些写操作给人审）
接入新网站 = AI 按同一协议起草 app/<新网站>/ 整个包 → 人工审（重点审：确认级别合不合理、写面该不该开）→ 引擎发现并装载。协议不变，变的只是包里的内容。

工作流的目标层 / 规则 / 数据层——都需要中间层转吗？需要，各转各的

你点名了三样东西，它们在链条上位置不同、转法也不同：
是什么中间层怎么转引擎怎么用
目标层
（干完活产出什么）		每步产出的契约：登记表/选型明细/报告——长什么样、渲染成什么包里声明产物槽 + builder + 表单源引用分发产出、广播产物事件（画布点开的就是它）
规则
（怎么干不出格）		两类：①纪律（必填/拍板/确认级别）②领域规则（配线规则/价格权限）①包里声明 decisions[]/左栏纪律；②只声明源引用——本体永远在 CPQ①闸机械执行 ②调用时 CPQ 自己执行
数据层
（怎么知道办完了）		探针：查库问题（"报价单落库了吗"）探针 DSL：填表声明"查哪张表、什么条件算过"每步结束跑探针，AI 说了不算
共同点：中间层转的是"声明"，引擎转的是"执行"，CPQ 转的是"事实"。三样现在都已部分运转（目标层✓、规则①✓、数据层部分写代码），缺口标在上表。
