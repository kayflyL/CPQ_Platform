商机详情页 · 手机版双抽屉方案

> 最后更新：2026-09-19 · 原型稿（仅视觉示意，非实现）

桌面三栏 = 左：四步流程轨道 / 中：当前节点工作台 / 右：协作与动态（审批时间线）。 手机版映射为双抽屉：左抽屉 = 流程轨道（切节点导航）、右抽屉 = 协作与动态（旁路信息）， 中间工作台独占全屏——当前要做的事永远在首屏，切流程与看动态都一步直达。 四张手机框：A 详情页主体 / B 左抽屉·流程轨道 / C 右抽屉·协作动态 / D 对比与分期。

信息架构变化

  • 主体（全屏）：顶部返回条（客户名 + 阶段徽标）→ 阶段工具条（流程 ☰ / ①-④ 进度 / 动态 N）→ 当前节点工作卡流（商机信息 + 各节点卡，折叠模型不变）→ sticky 动作条。
  • 左抽屉（流程轨道）：OpportunityProcessRail 原样入驻；节点选择即切换工作台并收抽屉。
  • 右抽屉（协作与动态）：ApprovalFlowPanel 原样入驻；pending 低毛利审批卡置顶直达裁决。
  • 退役：手机端「rail 占满整行」的堆叠特例与沉底的 board-aside。

分期落地

P1容器重构（仅 ≤768px）：stagebar + 左抽屉（Rail）+ 右抽屉（ApprovalFlowPanel）；工作台与 sticky bar 保持现状；桌面断点回归验证。
P2联动与未读：动态红点接 notifications（商机未读数，查看后清除）；两抽屉互斥 + 返回恢复（可选记忆抽屉开合）；裁决卡置顶排序。
P3打磨（可选）：边缘滑动手势；节点间切换的过场动画；阶段条长按预览节点摘要。

风险与兼容

  • 组件零改动：Rail / ApprovalFlowPanel 均整体复用，portal 工作台等其他消费方不受影响。
  • 审批可达性提升是安全项：裁决入口从「报价卡上方」变为「动态置顶」，权限门控（action.flow.approve.pricing）逻辑照搬，不新增裁决路径。
  • 角色裁剪视图：business/te/cost/quote 各角色看到的卡不同，双抽屉只动容器，裁剪逻辑照常生效；director 只读视图同样适用。
  • 与全局底栏共处：sticky 动作条已在现状实现中，仅需把 bottom 从 0 调到全局底栏上沿（62px + 安全区）。

与线索页 V2 的关系

  • 同一套语言：左抽屉 = 导航（流程轨道），右抽屉 = 旁路信息（动态/列表），与线索页「左图右表」同构——全站手机端形成统一的「中间主内容 + 双抽屉辅助」模式。
  • 线索页 V2 原型是否实施：等本页确认后一起拍板；两者互不依赖。
