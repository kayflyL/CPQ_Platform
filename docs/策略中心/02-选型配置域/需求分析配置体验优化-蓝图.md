# 蓝图：需求分析页面「配置体验」优化（阶段2 · 待确认）

> 目标：把需求分析页从「功能齐但没抛光」打磨成「像 n8n/Coze 一样的流程编排体验」。
> 本阶段只动**前端 UX 与信息架构**（palette / 画布 / 配置抽屉 / 试运行），不改后端执行语义、
> 不改节点能力、不碰确定性红线。所有新配置项仍走节点抽屉 / 前端常量，**拒绝硬编码**。
> 实施前先确认本蓝图；确认后按「P0 → P1 → P2」小步实施，每步跑回归（vue-tsc / npm test / build / 后端 pytest）。

---

## 1. 现状体检（逐项看过代码后的差距清单）

### 1.1 三处「节点元数据」重复且不一致（粗糙感主因之一）
| 位置 | 内容 | 问题 |
|---|---|---|
| `ReasoningFlowCanvas.vue` NODE_TYPES | 16 个新类型的中文名 + **英文后缀**（如「需求理解 understand」） | palette 与节点卡 label 带英文后缀，面向业务用户不友好 |
| `ReasoningNodeVf.vue` NODE_META | 节点卡片的 desc + sources | **只有旧类型**（extract/select_baseline/match_kp/compose/review/condition/…），10 个新类型（understand/gap_analyze/llm_ask/scene_decide/model_reason/kp_reason/spec_compliance/audit_fix/llm_confirm/text_clean）**全部没有 desc** → 节点卡只有 type 小字+label，下方说明空白 |
| `ReasoningNodeDrawer.vue` NODE_META | 抽屉顶部 alert 的节点职能 | 文案与上两处重复且口径不一 |

→ 应合并为**单一元数据 util**（`reasoningNodeMeta.ts`）：每个节点 = 中文名 / type / 职能一句话 / 数据来源 / 图标 / 组，palette、节点卡、抽屉标题共用。

### 1.2 发现的「看着能配、实际不生效 / 不能保存」问题（必须修）
1. **extract 节点抽屉不能保存**：画布 `CFG_TYPES` 把 extract 标为可配置（显示「可配置」tag），抽屉也渲染完整表单（5 张词表/别名/数量/正则），但抽屉 `CONFIGURABLE` **不含 extract** → 保存按钮不渲染，编辑无效。二选一：把它加进 CONFIGURABLE，或改成只读并引导「去需求理解节点配置」。
2. **scene_decide 的场景映射 JSON 是死配置**：抽屉渲染「场景映射（高级·JSON）」折叠项，但 `buildConfig('scene_decide')` 只回 `{ai_mode, fallback_scene, decide_threshold}`，**映射内容不保存**。要么接进 config，要么删掉该折叠项（权威在 system_config，本就该删）。
3. **`ReasoningNodeKey` 类型缺 `extract / spec_compliance / audit_fix`**：`updateNode` 靠 `as` 强转绕过，类型层已失真，应补全。

### 1.3 画布交互缺失（对照行业 flow builder 底座）
| 能力 | 现状 | 行业底座（n8n / Coze / React Flow 生态） |
|---|---|---|
| Palette | 点击添加、5 组、无搜索、无职能说明、无图标 | 搜索+分组+拖拽+一句职能+已用角标 |
| 拖拽添加 | ❌ 点击添加，坐标固定堆叠 | 拖到落点添加（点击保留） |
| 吸附/对齐 | ❌ | snap-to-grid（@vue-flow/core 内置，零依赖） |
| 自动布局 | ❌ | dagre/手写分层一键重排 |
| 复制/粘贴 | ❌（无 Ctrl+C/V） | 选区+内部边一起复制 |
| 连线校验 | 只有 condition true/false 警告 | 禁止自连/重复边/反向环 |
| 断链提示 | ❌ | 入度=0 非起点、出度=0 非终点 → 警告条 |
| 节点卡 | type 小字 + label +（旧节点有）desc | 图标 + 中文名 + 职能 + 来源 |
| 执行可视化 | 已有：running/done 高亮 + trace 回溯 + 步骤时间线 | 可加每步耗时 |

### 1.4 配置抽屉（Inspector）粗糙点
- 7 处 **JSON 文本框**（aliasesJson / cpuMemTypeRulesJson / sceneMappingJson / normalizeJson / charFixesJson / noiseJson / sc_cpu_mem_json）——业务用户手写 JSON 是最大门槛；
- 字段分组不统一（基础参数 / 高级·JSON / 各节点自定义 section）；
- 提示文案粗细不一：部分有 rf-hint，部分无；
- 「已保存（下次推理生效）」一刀切，实际规则类配置（词表/预算映射）是立即生效；
- 抽屉标题 `配置节点 · understand`，应显示中文名；
- 大量 **unreachable 旧节点分支**（normalize_input / slot_validate / confirm / llm / llm_understand / llm_agent / 独立 ask_user / 独立 clarity_check / scene_analysis）仍在模板里堆砌（~400 行），palette 已无法添加，仅旧 flow 版本激活时才会走到。

### 1.5 试运行 Playground
- 反问环节**只能看不能答**（「试运行不接回复，回复交互请到商机详情页」）→ 无法在页面内模拟完整对话流；
- 无每步耗时、无快速样例输入、错误只在顶部一行。

## 3. 改造蓝图（按区域 + 优先级）

### P0 · 信息架构与文案（低风险、纯前端，先做）
1. **新增 `reasoningNodeMeta.ts`**：16 节点统一元数据（中文名/type/职能/来源/图标/组）。palette、节点卡、抽屉标题、LLM 节点总览全部改读它。节点卡补全 10 个新类型的 desc + sources；label 去掉英文后缀（type 保留为小字 key）。
2. **Palette 升级**：搜索框（中文名/type/职能过滤）+ 每项一句职能 + 组内排序 + 「已用 ×n」角标 + 图标；extract 标「AI 失效兜底」。
3. **修复死配置**：extract 保存（加回 CONFIGURABLE）或改只读；scene_decide 删 mapping JSON 折叠项；`ReasoningNodeKey` 补全 extract/spec_compliance/audit_fix。
4. **空态引导**：画布无节点时显示「从左侧拖一个节点开始 / 加载默认图」；顶部 tip 换成分步说明（添加→连线→配置→试运行）。

### P1 · 画布交互（@vue-flow/core 内置能力优先，零新依赖）
5. **网格吸附**：`snap-to-grid` + `snap-grid=[16,16]`（内置，零依赖）。真正对齐参考线（snapline）@vue-flow 无内置，本阶段不做。
6. **拖拽添加**：palette 项 draggable，drop 到画布按鼠标落点定位（点击添加保留）。
7. **自动布局按钮**：手写分层布局（按边拓扑分层、同层纵排、层间横排；当前图基本线性，手写足够稳，不引 dagre 依赖）。
8. **复制/粘贴**：Ctrl+C/V（复制所选节点+内部边，粘贴生成新 id + 偏移，进撤销栈）；工具栏加按钮。
9. **连线校验 `isValidConnection`**：禁止自连 / 禁止同源同目标重复边 / condition 仅 true/false 出口；失败 message 提示。
10. **断链/孤立警告条**：入度=0 非起点、出度=0 非终点 → 顶部警告（与 condition 分支警告并列）。

### P2 · 配置抽屉与试运行（UX 精细打磨）
11. **JSON 文本框结构化**（按收益排序，逐个做）：
    - `char_fixes`（text_clean）→ 表格（from→to 行编辑）；
    - `noise_patterns`（text_clean）→ 表格（正则/说明）；
    - `cpu_mem_type_rules`（kp_reason / spec_compliance）→ 表格（CPU 正则 → 内存代际）；
    - `category_aliases`（kp_reason）→ 复用已有 SpecAliasEditor；
    - `scene_mapping` 已删（P0）；
    - 残余 JSON 保留但加「示例 + 校验 + 一键恢复默认」。
12. **抽屉统一排版**：每组字段 = 中文标签 + 作用一句 + 取值来源/默认值 + 生效方式（立即生效 vs 下次推理生效）；必填项红标。
13. **试运行交互式反问**：暂停 ask 时给「选项按钮 + 回复输入 + 继续」（本地模拟一轮回复 → 重新 POST /test-run），页面内即可走完整对话流。
14. **每步耗时 + 快速样例**：时间线显示耗时；「样例」下拉一键填模糊/详细/闲聊需求。
15. **清理旧分支**：按 §2「可删」清单删 unreachable 分支（决策点 2）。

## 4. 明确不做（避免过度设计 / 避免加依赖）
- 不引 dagre/elkjs/ELK（自动布局手写分层，当前图线性足够；以后图复杂了再评估）。
- 不做真·对齐参考线（snapline）——@vue-flow 无内置，自研复杂，用网格吸附替代。
- 不改后端执行语义、不加新节点类型、不改 `_dispatch`（那是「开发新能力」，不是配置体验）。
- 不做「从模板库一键导入整图」——有「加载默认图」需求再评估。

## 5. 实施顺序与验收
1. **P0**（文案/元数据/死配置修复）→ 验收：palette 可搜索、节点卡有职能、extract 抽屉可保存、scene_decide 无死配置。
2. **P1**（画布交互）→ 验收：拖拽/吸附/自动布局/复制粘贴/连线校验/断链警告逐项可用，undo/redo 不破。
3. **P2**（抽屉结构化 + 试运行增强）→ 验收：JSON 文本框减少、试运行可交互反问、字段提示完整。
4. 每步后回归：`npx vue-tsc -b` + `npm test` + `npm run build`；后端 `pytest`（基线 412 passed，本次若不动后端则不受影响）。
5. 收尾更新 CHANGELOG `[0.1.47]`。

## 6. 待确认决策点
1. **extract 抽屉**：加回「可配置」（可独立保存词表）还是改只读（引导去需求理解节点配）？建议**加回可配置**（extract 是真实兜底节点，独立词表有存在意义）。
2. **旧节点分支删除**：是否同意删 §2「可删」清单里的 unreachable 分支（~400 行死代码）？旧 flow 版本若被激活，对应节点抽屉会显示「无可配置参数」（优雅降级，不报错）。建议**删**。
3. **P2 结构化 JSON 的优先级**：按 11 里的顺序（char_fixes → noise → cpu_mem → aliases）做，还是有别的偏好？
4. **试运行交互式反问**（P2-13）：需要后端小配合（test-run 支持带上下文续跑），或在页面内用「把已收集信息拼进下一次请求文本」的纯前端模拟？建议**纯前端模拟**（不改后端）。
