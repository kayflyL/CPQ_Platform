## 修复模式沉淀（怎么改不返工）
1. **先最小复现 → 再改 → golden 追加 → 全量回归**（234 passed 兜底）；
2. **噪音过滤优先于抽取**：stage-1/R-8 跳过正则要随新格式持续补（I35~I94 大量为此类）；
3. **数据驱动 > 硬编码**：触发词/跳过正则/电源档位尽量进 DB flow 词表或 system_config，代码留兜底；
4. **判定要分锅**：系统错 → 改规则；技术员错 → 不匹配（格式差异不算错，如 cable/power cord 写法）；数据缺 → 诚实 unmatched；
5. **核心文件在长大**（requirement_intel_service ~1800 行 / candidate_search ~1600 行）：规则手册即"可维护性台账"，后续拆分/外置以本文档为索引。

## 学习闭环（四环）
```
① 成交/报价回灌：成交配置单归档 → 聚类 → 新方案候选 → 审核 → 入方案库
② 差异反馈：用户在 BOM 上改件/加件/删件 → 记录 → 周度分析 → 高频差异转规则
③ golden 回归：每轮新用例 → golden_cases.py → pytest 全量（现 234 passed / 21 用例）
④ 批量重放：规则更新后 → 全量历史配置单重放 → 差异报告 → 确认无回归
```
