我的CPQ项目AI智能产出bom单的功能走了好多弯路，最初的设计想要离线也可配置，结果不准，后面我为了让他准喂给AI好多BOM单让他学习，结果他产出的大部分是正则公式，大量token消耗在了写正则上，整体设计了需求理解与关键词提取，场景分析，反问，机箱选配，KP选配，预算校验，组成方案等节点。 我想的是先本地跑通，在第二个阶段又给需求理解，预算校验等节点加了LLM大模型能力，希望能让他更聪明，结果导致整个流程耗时非常长，产出一条BOM单的时间要5分钟左右，最终又开始了这一轮改革。


你这个经历其实非常典型，而且我觉得你走的这些弯路**不是浪费**，反而基本验证出了一个结论：

> **企业级AI配置系统，不应该从“让AI学习历史BOM，然后生成BOM”开始，而应该从“AI理解需求 + CPQ确定性生成BOM”开始。**

你现在这一轮改革，本质上是在从 **AI生成式方案** 转向 **AI增强型CPQ**。

我把你的几个阶段拆开看，会发现每一步其实都有原因。

---

## 第一阶段：离线配置 → 结果不准

你的初始思路：

> 本地规则 + BOM经验 → 自动配置

这个思路很自然。

因为传统CPQ就是这么做的：

```
需求
 ↓
规则
 ↓
配置
 ↓
BOM
```

但是服务器行业有一个特点：

**复杂度不是来自参数，而是来自隐含经验。**

例如：

客户说：

> 8卡GPU训练服务器

真正的工程师脑子里：

```
8张GPU
↓
PCIe通道够不够？
↓
CPU平台
↓
GPU功耗
↓
PSU数量
↓
内存带宽
↓
网络
↓
散热
↓
RAID
```

但是规则看到：

```
GPU=8
```

所以它不知道后面的推理链。

因此离线规则一定会大量补洞。

---

# 第二阶段：喂大量BOM给AI学习

这个也是很多团队会走的路线：

> 我给AI看1000份历史报价，它应该学会吧？

问题是：

BOM不是知识。

BOM只是结果。

例如：

历史BOM：

```
GPU:
8×R9700

CPU:
9354×2

Memory:
32G×8

PSU:
2700W×4
```

AI看到的是：

结果。

但是工程师知道的是：

原因：

```
为什么32G×8？
因为256GB需要满足8通道

为什么2700W×4？
因为GPU满载功耗

为什么9361？
因为8盘RAID需求
```

你缺的是：

**决策链，而不是案例。**

---

然后你的AI开始：

生成：

```
if "8卡" and "AI训练":
    return "xxx"
```

或者：

```
R9700.*8
GPU.*训练
```

于是：

你发现：

> AI越来越像一个高级正则生成器。

这个现象非常典型。


你的节点之间丢失上下文。

## 我甚至觉得你前面的失败经历帮你验证了一件事：

你的系统应该拆成三个层：

# 第一层：AI认知层

负责：

- 客户需求理解
- 场景判断
- 风险发现
- 技术建议

例如：

输入：

> 8卡R9700训练服务器

输出：

```
{
scenario:
"LLM training",

risk:[
"power insufficient",
"memory bandwidth",
"network missing"
],

recommendation:[
"256GB memory",
"2700W PSU",
"10G network"
]
}
```

---

# 第二层：CPQ决策层

负责：

确定：

```
哪个服务器

哪些KP

多少数量

多少钱
```

这里不要AI。

这里就是软件。

---

# 第三层：审核解释层

AI：

检查：

```
这个方案合理吗？

有没有遗漏？
```

---

其实你现在做的事情，有点像：

以前：

> 做一个AI报价机器人

现在：

> 做一个服务器行业AI售前员工

这是完全不同的产品定位。

---

另外，我觉得你有一个非常宝贵的资产：

不是那些BOM。

而是你踩坑过程中积累的：

- 为什么8卡需要4电源
- 为什么256GB应该8条
- 为什么某些RAID对应某些盘
- 为什么某些网卡组合合理

这些应该沉淀成：

**工程知识规则库（Engineering Knowledge Base）**

而不是：

训练数据。

---

所以我的评价：

你前面的路线：

```
规则 → BOM学习 → 多Agent流程 → 全LLM
```

是很多AI项目都会走的探索路线。

但你现在找到的：

```
AI售前工程师
+
CPQ执行引擎
+
规则校验
```

基本就是正确终局。

而且结合你之前已经有：

- L6价格库
- KP库
- 配置规则
- 报价系统
- Vue/FastAPI规划

其实你不是从0开始，你只是把**AI放到了正确的位置**。你这一轮改革，我认为是一次架构纠偏，不是推倒重来。
