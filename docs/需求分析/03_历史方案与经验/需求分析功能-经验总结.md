# 需求分析功能 · 经验总结

> 2026-10-21 重构：原对话原稿保留在同目录《需求分析功能-经验总结-对话原稿.md》，本稿按版本时间线整理成正式复盘。事实与数字锚定 `docs/CHANGELOG.md` 0.1.31~0.1.58 及 2026-08-10 智能化改革各条目。
> 配套阅读：`01_架构与契约/需求分析skill-技术架构.md`（现行权威快照）。

## 0. 一句话结论

这条功能线走过三个版本：**纯规则流水线 → 流水线节点各自加 LLM（AI 套 AI）→ AI 唯一大脑 + 确定性引擎**。核心教训一句话：**AI 的位置是架构决策，不是节点参数**——智能放错了层，往里加多少次模型调用都救不回来。

## 1. 版本演化

### 第一版 · 纯规则流水线（2026-07 下旬 ~ 08 初）

- **设计**：十几个节点的线性链（需求理解 → 关键词提取 → 场景分析 → 反问 → 机箱选配 → KP 选配 → 预算校验 → 组装…），纯正则 + 词表 + 死规则，出发点是"离线也能跑"。
- **症状**（8 卡 GPU 真实需求实测，0.1.51 背景）：内存配出 16G×1、RAID 直接缺失、网卡配出 400G、电源估 2000W——又慢又错。
- **根因**：服务器配置的复杂度不在参数，在隐含经验推理链（8 卡 → PCIe 通道 → 平台 → GPU 功耗 → PSU 数量 → 内存带宽 → 网络 → 散热 → RAID），规则只看到 `GPU=8`，后面的链它推不出来。

### 旁支 · 喂历史 BOM 让 AI 学（2026-07，与第一版并行）

- **设计**：把大量历史 BOM 单喂给 AI，指望它学会产出。
- **结果**：AI 产出的大部分是正则公式，大量 token 烧在写正则上——"AI 越来越像一个高级正则生成器"。这批正则（`requirement_parser` 包）在 0.1.56 物理删除时约 **-2600 行**。
- **根因**：**BOM 是结果，不是知识**。AI 看到"32G×8"，学不到"为什么 32G×8（256GB 要满足 8 通道）"。缺的是决策链，不是案例。

### 第二版 · 流水线骨架 + 智能化节点分散注入（2026-08-04~09，v0.1.36~0.1.48，**截图即此版**）

- **设计**：第一版的链不动，把其中若干节点标成"LLM 节点"——需求理解与解析、AI 智能反问、方案校验；方案校验挂三路输入（选型配置规则 / 历史方案配置库 / 客户预算校验），反馈不合格回选机型重选，置信度 >80% 输出排行前三给用户选。思路是"规则不聪明，就给关键节点各加一个 AI"。
- **实际运行时 LLM 介入点比图上画的还多**，形成三层 AI 套 AI：
  1. **编排层**：每步调一次 LLM 决策"下一步跑哪个节点"（约 10 次 × ~8s；拓扑已确定时纯属重复劳动，0.1.50 定性）；
  2. **节点层**：理解节点 LLM 一次性大填表（10+ 字段）；机型、配件节点内部各自跑 ReAct 循环（0.1.37 节点级 enable_llm 开关注入 extract/scene/review 三节点，后续 kp_reason 也是 ReAct）；
  3. **裁判层**：llm_audit 再用一次 LLM 审方案。
- **症状**：
  - 一条 BOM **6~10+ 次模型调用，约 5 分钟**；
  - 理解节点 40-60% **空回**——reasoning 模型对"10+ 字段一次性大填表"过度思考，把 max_tokens=8000 烧在思考阶段（finish_reason=length），单步 42-64s；
  - 需求点名 Intel 平台、目录里 AI 机型全是 Orion → series 硬过滤 **plans=0**，白等 4 分钟没方案；
  - **上下文漂移**：需求理解说"这是 AI 训练"、场景分析说"这是推理场景"、KP 节点推荐 400G 网卡——每个 LLM 节点各理解各的，没人对全局负责。
- **根因**：把一个高级售前拆成了流水线，再给每个工位各发一个小大脑。真实售前是**同时**思考的（训练 → 要 GPU → GPU 要功耗 → 要什么平台 → 要什么网络），不是先理解、暂停、再场景分析。**节点切面本身就在丢上下文，这个洞 LLM 补不上**——给切面加智能，只会得到 N 份互相矛盾的理解。

### 第三版（现行）· AI 唯一大脑 + 确定性引擎（2026-08-10 改革 v0.1.49~0.1.58 → 09-12 定调 → 09-14 插座插头收口）

改革主轴（细节见 CHANGELOG 0.1.49~0.1.58）：

- **混合脊柱编排**：LLM 只做决策、规则跑腿。`_needs_llm_decision` 门控——信息明确就按拓扑确定性跑，只在反问/选型落空/收尾总结这些真正需要判断的点让 LLM 介入；编排 LLM 决策从 ~10 次降到 0-2 次。
- **理解拆步子任务**：一次性大填表 → 4~5 个聚焦子任务并行，失败单独便宜重试（78s+空回 → **~9s 稳定**）。
- **AI 提议、引擎落地**：KP 走「LLM 提议 + 库校验」（`pick_kp_parts`），真实料号/价格/政策/白名单锁在引擎里，防幻觉。
- **确定性红线**：compose / spec_compliance / audit_fix / review 组成的"重建脊柱"LLM 不可跳过、不可改数据。
- **独立 judge**：llm_audit 升级独立裁判人设，防"同模型自批判塌缩"。
- **执行预算**：墙钟/步数/工具调用/反问轮数全可配，超限按确定性链收敛，不再无限跑。
- **诚实降级**：AI 不可用就明说"请手动选型"，不拿正则假装理解（0.1.53/0.1.55/0.1.56/0.1.58 把假智能路径物理清除 4000+ 行，正则理解彻底退出）。
- **多级放宽**：exact → same_series → same_form → all 替代硬过滤，每级放宽带白盒说明（根治 plans=0）。

效果（同一 8 卡需求）：**258.5s 无方案 → 70-95s 出方案**；模糊需求 20.5s 反问"主要用途？"；中等需求 51.4s 直接出方案。

后续定形：收敛为 6 节点链 `input → agent_fill → model_reason → kp_reason → compose → output`；编排壳不认识任何具体节点（插座插件 + 抽屉插头 + 步进闸门，09-14 收口）。09-12 用户定调心智模型：**workflow 不是驱动器、是指引**——AI 是同一个大脑先后扮演两个业务角色（线索登记员 → 方案配置技术员），交接靠表（产物=真实业务表，技术员只认单据），步进闸门只是"表填好才放行"的护栏，不决定怎么干。

## 2. 「AI 套 AI」专门复盘

> 回答的问题：截图里"智能化节点分散在各个节点"就是当时的情况吗？——是，那就是第二版；且实际运行的 LLM 介入点比图上标的三个"LLM 节点"还多。

- **名词解剖**：AI 套 AI = 确定性流水线每走到一个"智能节点"就起一个独立 LLM 会话（各自 prompt、各自上下文、互不通览全局），外层还有另一个 LLM 在决定节点顺序——**外层的 AI 套着节点里的 AI**。任何一步都"看起来更聪明了"，系统级效果却是延迟 ×N、理解互相矛盾、token 预算烧光。
- **为什么会走到这步**：局部修补思维——"哪一步不准就给哪一步加 AI"。每一步单独评估都是提升，没有人在系统层算总账（调用次数、总延迟、全局一致性）。
- **事后判据**：**如果一个流程既要 LLM 决定步骤顺序、每个步骤内部又各有一个 LLM，这个架构就已经错了**——正确做法是合并成一个大脑，让它用工具去够确定性能力，而不是用流水线把一个大脑切成 N 个。

## 4. 教训清单

1. **AI 的位置是架构决策，不是节点参数**。正确分层：AI 认知层（理解需求/判断场景/发现风险/给建议）＋ CPQ 决策层（哪个机型、哪些配件、多少数量、多少钱——**这里不要 AI，这就是软件**）＋ 审核解释层（方案合理吗、有没有遗漏）。
2. **BOM 是结果不是知识**。该沉淀的是工程知识规则库（为什么 8 卡要 4 电源、为什么 256GB 配 8 条、为什么这 RAID 配这盘），不是训练数据，更不是正则。
3. **别把一个高级售前拆成流水线**。节点切面天然丢上下文；给每个节点加 LLM 得到的是 N 份互相矛盾的理解，不是 N 倍智能。
4. **单一大脑 + 步骤指引 + 护栏**。workflow 告诉 AI 走哪些步、每步交什么表；闸门只验表填没填好，不指挥怎么干；跨步骤信息必须进表，不能只活在聊天里。
5. **确定性的事交给确定性代码**。价格、数量、兼容、白名单永远引擎算；AI 只提议，落地必回库核对。
6. **延迟是一等公民**。模型调用次数本身就是成本、延迟与故障面；"小模型 × 多次"不等于"聪明"。
7. **诚实降级好过假装智能**。AI 不可用就明说并转手动选型，不拿正则装理解、不跑旧链假装出方案。
8. **假智能路径要物理删除**，别留"画布兼容"后门——留着就总有人（包括未来的自己）把它捡回来。
9. **演化不是浪费**。每一版都验证了一层边界：规则不够 → 数据不够 → 局部智能不够 → 位置放对才行。
