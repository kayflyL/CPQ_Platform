# 选型配置引擎 — 设计方案 v2.1(底座先行)

> 2026-11-06 定稿。两部分:**第一部分 = 传统引擎底座**(用户人工配置服务器时发生作用,主战场,允许大改);**第二部分 = AI 层兼容**(只保证插头不失效,非主战场)。v2.1 修订:①同行明确踩雷的设计坚决剔除,不留沉没成本、不做妥协兼容;②补页面变动清单与窗口原型(docs/prototypes/选型配置引擎-底座人工面原型.html);③铁律:零硬编码,所有约束用户可增改。

# 第一部分 底座

## 1.1 行业调研

### 案例 A:PCPartPicker(消费级 PC 装机,置灰体验标杆)
- **两层防线**:①选择时过滤——选了 Intel CPU,主板下拉实时只剩兼容型号;②整单校验——配完列表再挂警告标签。另有功耗估算器帮选 PSU。
- **底层是数据不是规则**:兼容判定 = 「零件结构化属性 vs 已选零件属性」的谓词(插槽/芯片组/形态/功耗),规格直接取自厂商数据。已知短板也是数据短板:物理兼容数据不全时判定失准。
- 借鉴:**先有结构化属性数据才有实时过滤;置灰可信度上限 = 数据完备度;可从属性推导的判定绝不写成规则**。

### 案例 B:Dell / HPE 服务器配置器(同行业,现实对标)
- 规则/矩阵式:每机型兼容矩阵(CPU 支持清单、NIC 矩阵、背板-盘位-RAID-线缆关系)+ 数量/槽位限制 + 功耗容量与冗余校验。深度校验(热/固件)业界也未全自动化。
- 借鉴:兼容矩阵是**结构化数据**不是文本规则;功耗预算是一等公民;服务器配置器做到这个水准即行业主流,不需要求解器。

### 案例 C:Tacton(复杂装备 CPQ,约束式 vs 规则式)
- 规则式三死穴:**规则数量爆炸、规则顺序依赖、维护不可扩展**(同事实可多路径推导时,规则式会为每条路径写一条规则)。约束式声明事实间关系,次序无关。
- 借鉴:约束语义与求值次序解耦;**"用规则枚举机器可推导的事实"是规则爆炸的起点,必须在 schema 设计期防住**。

### 案例 D:Configit(汽车,虚拟制表)
- 编译思想(全部合法配置离线编译一次)+ 一份约束模型跨销售/工程/制造多消费面。
- 借鉴:**模型与消费端解耦**——约束模型一份,人工 UI / 公开向导 / 二期 AI 全消费同一判定。我们规模不需要离线编译。

### 案例 E:SAP 变式配置 LO-VC(150% BOM)
- 超集 BOM 按客户选择裁剪出订单 BOM。选配语义 = **"从全量结构裁剪+升数量"**,不是往空单子平铺加件。
- 借鉴:base_config 即超集 BOM,选配语义基线挂基准配置。

### 共性提炼(目标形态五要素)
1. **判定唯一出口**:一份约束模型,多消费面全走同一引擎,零第二份求值逻辑。
2. **交互一致性**:每选一步引擎全量重算,输出完整世界状态(可选/置灰+原因/缺失/补全/资源账本),不是事后告警清单。
3. **结构化属性优先,规则兜底**:属性可推导的不写规则;规则只装业务口径;表达与次序无关。
4. **资源账本一等公民**:功耗、槽位、线缆是常显账本,不是保存时才查的检查项。
5. **数据完备度决定引擎上限**:数据盘点与引擎建设同等重要。

## 1.2 剔除清单(同行踩雷 × 现状对号,坚决剔不妥协)

选型域现状盘点(2026-11-06 连库核实):**14 条 active 规则**(derive 6 / exclude 3 / recommend 5)。逐条裁决:

| 现状设计 | 行业判词 | 裁决 |
|---|---|---|
| `contains` 字符串条件寻址(`kp.CPU.spec.text contains '兆芯'`) | 案例 A:属性谓词才是正解;字符串包含对别名/大小写/型号变更脆弱 | **剔除**。选型域 14 条一次性重录为结构化属性谓词;选型域 contains 求值路径删除,不保留"旧规则照跑" |
| 数量上限类 recommend 规则 ×5(id 25/26/26/35/36/37:CPU/内存/GPU 不超机型上限、盘数不超盘位、电源数不超槽位) | 案例 A/C:**机器可从 base_config 槽位数据推导的事实写成规则 = 规则爆炸起点**;案例 A 里这类判定全是数据驱动的实时钳制 | **从规则中剔除**。降级为槽位钳制(数据驱动,§1.3 协议里 slots 自动生效);这 5 条规则直接删除 |
| 「同类不混搭」exclude ×3(id 22/23/24:内存/CPU/GPU 各一条,每条 when+then 全套重复) | 案例 C:同一事实的 N 条规则副本 = 维护债 | **收敛为一个类目级「同类一致」约束**:治理面按类目勾选(内存☑ CPU☑ GPU☑ …),一条配置管全部,新增类目勾选即生效 |
| 规则顺序依赖(eval_assign_value 按顺序 short-circuit、"更具体的放前面") | 案例 C 明文死穴 | **剔除**。改显式 priority;同字段多规则命中且 priority 相同 = 模型错误上报治理面,不静默取先 |
| 前端本地求值复制体(`selectionEngine.ts`) | 共性 1:零第二份求值逻辑 | **删除**,无过渡双跑期 |
| 「方案整体跑一遍→告警清单」协议 | 共性 2:交互一致性 | **剔除**,resolve 协议唯一 |
| derive 线缆/背板规则 ×5(id 17-21) | 业务口径(每 NVMe 盘一根线、含 NVMe→三模背板),属性推导不出来 | **保留**,重录为结构化算术 derive(数据源指向槽位字段,不再是 spec text contains) |

保留不动:规则本体住 `rules.compatibility_rules`(DB 唯一源)、domain 分域、命中计数;`kp_parts.applicable`/base_config 槽位/specs.tdp 能力事实雏形;选型配置页定位 = 规则治理面。明确不做:不上 SAT/CSP 离线编译(规模不匹配);不重构 base_config 为 150% BOM 表结构(借思想不借结构)。

## 1.3 目标形态

### 架构(三层)
```
约束数据层(补数)   kp_parts.applicable / specs(接口、TDP、容量)/ base_config 槽位功耗
约束规则层(重录)   rules.compatibility_rules(domain=selection):结构化属性谓词
                     + require/exclude/derive/recommend 四动作
                     + 新增 requires/excludes/resource/同类一致 四类约束
                     + priority 显式次序无关
执行器(新,单点)   后端 selection_gate 服务,唯一判定出口
```

### resolve 协议(引擎唯一输出形状)
```
POST /api/selection-gate/resolve
  入参:{ context }   # 机型/base_config + 已选件(类目→[{pn,qty}]) + 商机维度
  出参:{
    options:   { <类目>: { allowed:[pn…], blocked:[{pn, reason, ruleId, cause}] } },
    violations:[{ severity: conflict|require, ruleId, name, desc,
                  caused_by:[pn…], resolutions:[…] }],
    derived:   [{ category, qty, basis }],
    budget:    { psu_load_w, psu_capacity_w, slots:{cpu:{used,max}, dimm:…, bays:…} },
  }
```
槽位钳制来自 budget.slots(base_config 数据),不需要规则;线缆/背板派生来自 derive 规则。**消费语义(v2.2 修订,2026-11-06 用户拍板):不兼容件干脆不出现**——配置面(报价工作台/机箱弹窗/公开向导)只渲染 `options.allowed`,blocked 明细不下发配置面(只进治理面试跑与审计,支持"查被过滤了什么");类目下拉顶部留一行过滤统计小字(如"已按兆芯平台过滤 2 件"),不做置灰、不做原因悬停。

### 页面变动清单(肉眼可见的变化,窗口原型见 §1.3.1)

| 页面 | 变动 |
|---|---|
| **报价工作台**(/quote 主战场) | ①KP 类目卡选件下拉:**不兼容件直接不出现**,顶部一行过滤统计;②数量步进:超槽位**直接钳制**(不再事后告警);③新增**「装配账本」磁贴**:功耗条(实时 CPU TDP+盘+卡 vs PSU 容量)+ 槽位占用格;④派生补全建议(线缆等一键加入);⑤**保存前轻量校验**:常规手选一路全绿无弹窗,只兜底四类残留场景(Excel 导入 BOM 带入不合规件、切换机型后已选件失效、组合冲突、缺必配),给快速修复项+"保留并知悉"留痕 |
| **机箱配置弹窗**(L6ChassisConfig 四步向导) | 每步候选同过滤/钳制;顶部加微型账本摘要条 |
| **公开向导**(ConfigWizard,门户匿名) | 同过滤+简化账本(无价格);行为与报价工作台完全一致(同端点) |
| **选型配置页**(治理面) | 规则编辑器新增四类约束的**表单化编辑**;试跑轨迹升级为逐规则归因(逐条件真值 + 牵涉已选件 + 命中次数 + 被过滤件明细) |
| 不动外观 | 机型目录页、商机详情、导出模板、需求分析全链路 |

### 1.3.1 窗口原型
`docs/prototypes/选型配置引擎-底座人工面原型.html`——四帧:①报价工作台 KP 配置区(置灰下拉+装配账本+派生补全建议);②保存拦截弹窗(归因卡+修复选项+豁免留痕);③机箱配置向导第 3 步(微型账本+候选置灰+步进钳制);④治理面(新增约束类型表单+逐规则归因试跑轨迹)。原型为视觉权威,实现照搬;视觉值以 tokens.css 等价值落前端。

### 预期效果(验收 = 原型场景在真实页面复现)
1. 选兆芯机型后,不兼容主板**不在下拉里出现**,顶部一行"已过滤 2 件";
2. 内存步进到槽位上限即钳住,不存在"多选了再告警";
3. 功耗账本常显,超载红/接近黄;
4. 派生补全(线缆/背板)一键加入或忽略;
5. 保存前轻量校验只兜底残留场景(导入/机型切换/组合冲突/缺必配),给快速修复项,"保留并知悉"须留痕(操作人/时间/原因);
6. 治理面新增/修改规则,试跑归因可见(含被过滤件明细),报价工作台下一秒生效。

## 1.3.2 约束机制全景(现状 + 底座新增后,有哪些东西在拦"配错")

| # | 机制 | 在哪 | 管什么 | 状态 |
|---|---|---|---|---|
| 1 | **基准配置(base_config)** | 设置-服务器管理-基准配置 | 机箱能力事实:槽位上限(max_cpu/max_dimm/bays/psu_bays/gpu_slots)、默认料件(底盘件/后面板默认卡/线缆/PSU)、系列/形态——选配的"超集 BOM" | ✅ 已有;底座把槽位消费成**实时钳制**(现在只出告警) |
| 2 | **料号库属性数据**(kp_parts / parts_master) | 管理面料号库 | 硬件主数据:specs(接口/插槽/容量/TDP)、`applicable` 系列适配字段 | ✅ 字段已有;**数据缺口待 S1 盘点**(GPU 类 applicable 0/36) |
| 3 | **选型配置引擎(兼容规则)** | /strategies/selection | 业务口径约束:requires/excludes/资源预算/同类一致/派生 | ✅ 已有雏形,底座重录升级 |
| 4 | **系列过滤(applicable 消费)** | AI 落料 `_SeriesScopedRepo` / (人工面待接线) | 机型系列锁定后,不适用配件进不了候选 | AI 侧已硬;**人工面目前未接,底座 S3 接上** |
| 5 | **数量物理闸(baseline_qty_cap)** | AI 落锁链路 | 配件数量不超槽位 | AI 侧已硬;人工面由底座的钳制等效覆盖 |
| 6 | **功耗/资源账本** | — | PSU 容量冗余、PCIe 槽位分配 | ❌ 现在完全没有,底座新增 |
| 7 | 价格权限(price_ok/price_mask) | 认证层 | 价格可见性,不是兼容约束 | ✅ 已有(不属本引擎,列出防混淆) |

一句话:**底座上线后,人工选配被"数据(基准配置槽位+料号属性)过滤在前、规则(业务口径)校验在后、账本(功耗/槽位)常显兜底"三层拦住;AI 链路已走前两层,底座补齐人工面并新增第三层。**

## 1.4 实施步骤(四步)

**S1 数据先行**:①选型域规则重录映射(已盘点 14 条,裁决见 §1.2,重录量 = 8 条 derive/exclude + 4 类新约束表单);②属性数据完备度盘点:applicable 覆盖(GPU 类已知 0/36 未填)、CPU/主板/RAID/网卡接口字段、全类目 TDP、base_config 槽位。缺口清单交用户录入,**不发明种子值**。

**S2 引擎 v2(selection_gate)**:谓词算子库(纯函数独立单测:字段精确/集合/数值比较 + requires/excludes/resource/同类一致/算术 derive);resolve 端点;与旧 `evaluate_rules` 对拍夹具(仅作迁移验收,验收过即删旧求值路径);`plan_rule_apply` 切 gate(选型域规则重录完成后切,见第二部分)。

**S3 人工面接线**:报价工作台(下拉置灰/步进钳制/装配账本磁贴/归因卡/保存硬门)、L6ChassisConfig、公开向导三面接同一 resolve;前端 `selectionEngine.ts` 求值函数删除;原型照搬,视觉值走 --cpq-* token。

**S4 治理闭环**:试跑轨迹逐规则归因;回归电池(存量方案快照批量 resolve diff);规则覆盖盘点收尾。

## 1.5 零硬编码铁律(规则用户可增改)

- **机制/业务分离**:谓词算子、动作种类、resolve 协议是代码(机制);字段路径、阈值、清单、数量、优先级全部住规则 body / 数据表(业务),代码零业务值;
- **新约束类型上线即配**四类新约束(requires/excludes/resource/同类一致)在治理面同步提供表单化增删改,不允许"代码能算、界面不能配"的约束存在;现有五动作编辑器照常;
- **改完即生效**:治理面保存 → invalidateRules → 三个消费面下一秒生效(现有机制沿用);
- **槽位钳制不需要"配"**:它读 base_config 数据,基准配置编辑器就是它的录入面,不新增平行配置入口;
- 数量基线/上限等业务数值永远住管理面,代码不发明默认值(既有铁律沿用)。

## 1.6 边界与风险
- **降级纪律**:规则/数据读取失败 = 引擎放行(fail-open),但放行必须留白盒痕迹(前端降级徽标+后端日志)——置灰悄悄失效成"全可选"是禁区;
- **性能**:288 件 × 十几条规则全量求值 <1s,每次选件后调 resolve 无压力,不做缓存;
- **权限**:resolve 只读匿名可达(公开向导);不带价格(价格面照旧 price_ok);规则编辑收 page.strategies;
- **零迁移**:新 schema 全进规则 body JSON,零表迁移、零 startup migrate 钩子(吸取 v9 回退教训);
- **数据债**:S1 缺口未补齐的维度先只做规则级置灰,属性级判定降级为整单校验,前端如实标注判定依据。

# 第二部分 AI 层兼容(只保不失效)

| AI 侧插头 | 消费什么 | 影响 | 策略 |
|---|---|---|---|
| `plan_rule_apply.apply_plan_selection_rules` | 跑 selection 域规则产 `chassis_signals` + `selection_alerts` | **直接受影响**(换引擎+规则重录) | 内部改调 selection_gate;**输出字段形状冻结**,消费端零改动;切闸前提 = 选型域规则重录完成,对拍夹具验收 |
| `catalog_derivations_for_registration` + 影子校验 | 赋值型 derive(domain=requirement) | 间接受影响 | **需求域规则零迁移**;新引擎保留赋值型 derive 同语义(priority 语义对单规则域透明) |
| 知识化注入 / 节点知识绑定(按 rule id) | requirement 域规则文本与 id | 不受影响 | 需求域零改动 |
| `select_parts` 系列过滤 + 数量物理闸 | `_SeriesScopedRepo` + `baseline_qty_cap` | 不受影响 | 与新底座同向,原样保留,二期自然归一 |

**兼容三铁律**:①需求域零改动;②AI 消费的输出契约冻结(chassis_signals/selection_alerts 形状,对拍夹具覆盖);③AI 侧唯一允许改动点 = plan_rule_apply 内部换调 gate,接口签名与输出不变。

二期展望(AI 三道闸消费同一 resolve 端点)不在本版展开,底座稳定后接线即可。
