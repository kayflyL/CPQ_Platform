# AI 写面台账（S3：每个写操作要么有契约+确认+回读，要么明确声明 AI 不碰）

> 定位：终局判定标准 S3 的显式化账本。业务系统约 216 个写端点（2026-10-31 实测
> POST 127 / PUT 49 / DELETE 39 / PATCH 1），AI 能触达的写操作以本表为准——
> **未登记 = AI 摸不到**（工具白名单机制天然默认安全），登记即显式接入。
> 迁移基线：2026-10-31 实测 AI 契约写工具 13 个 ≈6%，本表随域接入滚动更新。

## 未接入（默认 AI 不碰；接入 = 按五步走，不做隐式开口）

- **全部删操作**（DELETE 家族）：AI 永不删业务数据。
- 人事/权限/角色/系统配置：AI 不碰。
- 其余 ~200 写端点：按域逐步评估。评估口径——①操作三件套齐不齐（结构化出入参/函数内权限/可安全重试）；②确认级别建议（none 仅限幂等低影响）；③回读函数写得出写不出。
- 接入五步：① 域服务函数补齐操作三件套 → ② 域清单 `tool_manifests/<域>.py` 加一条（含契约）→ ③ 写后回读函数挂 verify → ④ 全量回归 + 考卷 → ⑤ 本表登记。

## 机制护栏（为什么这张表敢承诺"未登记=摸不到"）

1. 工具白名单：大脑每步只见 `enabled_tools` ∩ 同事 tool_ids，未声明工具不在注册面。
2. 保守默认：未登记契约的写按最高档确认（stage+consent）。
3. 四闸 + 审计：写路径必过确认闸/决策闸/问答协议，registry 写路径统一回读+落账
   `rules.agent_audit_log`（查询 `GET /api/assistant/admin/write-audit`）。
4. 宪法棘轮：机制散文/提示词常量只减不增，声明是唯一出处。
